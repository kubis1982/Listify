# EN/PL Internationalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user read the whole Listify interface in English or Polish and switch between them instantly from the header, with the choice remembered across sessions.

**Architecture:** A hand-written `I18n` service holds the current language in a signal and exposes `t(key, params?)`. Because `t` reads that signal, every template expression calling it re-evaluates when the language changes — no pipe, no reload, one build. The English dictionary is the source of truth; the Polish one is typed as `Record<TranslationKey, string>`, so a missing or misspelled key fails the build.

**Tech Stack:** Angular 22 (standalone components, signals, `@Service`, Signal Forms), TypeScript 6 strict, Vitest + jsdom via `@angular/build:unit-test`, `@angular/cdk/dialog`, `@angular/material/autocomplete`.

**Spec:** `docs/superpowers/specs/2026-09-19-i18n-en-pl-design.md`

## Global Constraints

- Branch: `feature/i18n-en-pl`. It already exists and holds the spec commits.
- Angular v22 house rules from `CLAUDE.md`: no `standalone: true`, no explicit `ChangeDetectionStrategy.OnPush`, no `@HostBinding`/`@HostListener` (use the `host` object), no `ngClass`/`ngStyle`, never import `CommonModule`, `inject()` over constructor injection, `@Service` over `@Injectable({providedIn: 'root'})`, native control flow (`@if`/`@for`), signals for state, `computed()` for derived state.
- TypeScript: strict; never `any`, use `unknown` when uncertain.
- Accessibility: must pass AXE and WCAG AA. Every `aria-label`, `title` and visible string is translated together; `document.documentElement.lang` must follow the selected language.
- English is the default and fallback language, and the source language of the dictionary. Existing English strings are moved **verbatim** — changing an English wording breaks the existing test suite, which asserts on those exact strings.
- Storage key: `listify:language`, matching the existing `listify:*` convention.
- Placeholder syntax in translation values is `{name}` — a single pair of braces around an identifier.
- Commits: Conventional Commits, description in English, no `Co-Authored-By` / AI-attribution footer (per the repo's `git:commit` skill).
- Test command shape: `npx ng test --include <path-to-spec> --watch=false`. Full suite: `npx ng test --watch=false`.
- Dictionaries are statically imported, never fetched — the app is a PWA and must translate offline.

- [ ] **Step 6: Write `i18n.service.ts`**

```ts
import { effect, Service, signal, Signal } from '@angular/core';
import { DEFAULT_LANGUAGE, Language, LANGUAGES } from './language.model';
import { en, TranslationKey } from './translations/en';
import { pl } from './translations/pl';

const STORAGE_KEY = 'listify:language';

const DICTIONARIES: Record<Language, Record<TranslationKey, string>> = { en, pl };

function isLanguage(value: unknown): value is Language {
  return typeof value === 'string' && (LANGUAGES as readonly string[]).includes(value);
}

function readStoredLanguage(): Language | null {
  try {
    const stored = localStorage.getItem(STORAGE_KEY);
    return isLanguage(stored) ? stored : null;
  } catch {
    // localStorage unavailable — fall through to browser detection.
    return null;
  }
}

function readBrowserLanguage(): Language | null {
  const base = navigator.language?.toLowerCase().split('-')[0];
  return isLanguage(base) ? base : null;
}

function interpolate(template: string, params: Record<string, string | number>): string {
  return template.replace(/\{(\w+)\}/g, (placeholder, name: string) =>
    name in params ? String(params[name]) : placeholder,
  );
}

@Service()
export class I18n {
  private readonly current = signal<Language>(
    readStoredLanguage() ?? readBrowserLanguage() ?? DEFAULT_LANGUAGE,
  );

  readonly language: Signal<Language> = this.current.asReadonly();

  constructor() {
    effect(() => {
      const language = this.current();
      document.documentElement.lang = language;
      try {
        localStorage.setItem(STORAGE_KEY, language);
      } catch {
        // localStorage unavailable or full — the choice stays in memory for this session.
      }
    });
  }

  setLanguage(language: Language): void {
    this.current.set(language);
  }

  /**
   * Declared as an arrow-function property, not a method, so a component can
   * expose it directly (`protected readonly t = inject(I18n).t`) and call it
   * unqualified from its template. Reading `current()` inside is what makes
   * every `t(...)` expression in a template re-evaluate on a language change.
   */
  readonly t = (key: TranslationKey, params?: Record<string, string | number>): string => {
    const template = DICTIONARIES[this.current()][key] ?? en[key];
    return params ? interpolate(template, params) : template;
  };
}
```

```ts
export function toExportFilename(listName: string): string {
  const slug = listName
    .trim()
    .toLowerCase()
    // Split accented letters into base + combining mark, then drop the marks,
    // so "świąteczne" slugs to "swiateczne" rather than losing the letters
    // entirely to the [^a-z0-9] filter below. `ß` has no such decomposition
    // and needs its own replacement.
    .replace(/ß/g, 'ss')
    .normalize('NFD')
    .replace(/[̀-ͯ]/g, '')
    .replace(/[^a-z0-9]+/g, '-')
    .replace(/^-+|-+$/g, '');
  return `${slug || 'shopping-list'}.json`;
}
```

Polish `ł` is worth checking: it does not decompose under NFD either. If the test suite or a manual check shows `ł` being dropped, add `.replace(/ł/g, 'l')` next to the `ß` line.
